# Чек-лист ручного тестирования

Автоматика (гоняется командами, подробности в README → «Тесты»):

```bash
cd server
.venv/bin/python scripts/test_report.py     # все уровни + отчёт с покрытием
.venv/bin/python -m pytest                  # только быстрый набор
.venv/bin/python -m pytest -m integration   # реальная ECAPA на синтезе
.venv/bin/python -m pytest -m e2e           # встречи целиком на одноразовом сервере
cd ../client && npm run typecheck && npm run build
```

Ниже — то, что автоматика проверить не может: реальный микрофон, звонки,
железо. Проходится перед показом/релизом; ✅/❌ и заметки — прямо в таблице.

## Перед полным прогоном тестов

`scripts/test_report.py --all` поднимает настоящий сервер и грузит GigaAM —
нужно **~2 ГБ свободной памяти**. На 8 ГБ сначала:

```bash
docker compose down          # контейнер держит ~1.8 ГБ
```

Иначе все e2e упадут с `TimeoutError: сервер не поднял ASR` — это нехватка
памяти, а не поломка кода (проверено: с освобождённой памятью те же тесты
проходят).

## Почему отчёт генерируется, а не пишется

Показательный случай из истории репозитория: коммит `e4281fd` добавил в
`tests/conftest.py` строку `STENOGRAF_PRELOAD_ASR=false` (чтобы юнит-тесты не
грузили модели). Флаг наследовался дочерним uvicorn в e2e — и **все 10 e2e-тестов
перестали проходить**. В том же коммите в отчёте было написано «E2E — 10 тестов,
все зелёные».

Никто не заметил, потому что число было вписано руками. Поэтому теперь
`TEST_REPORT.md` генерируется из JUnit XML: сломанный тест сразу виден в отчёте.
