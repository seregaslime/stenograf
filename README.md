# 🎙️ Стенограф

Десктоп-приложение для протоколирования встреч: превращает речь с **микрофона**
и **системного звука** (корпоративный звонок, вебинар) в текстовый чат в реальном
времени, различает голоса участников и по окончании встречи составляет протокол
с помощью **локальной LLM** — данные не покидают машину или контур организации.

## Возможности

- **Живая транскрипция** — реплики появляются в чате через 1–3 секунды после фразы
  (silero-VAD + сменный ASR-движок). Движок и модель переключаются прямо в
  настройках без перезапуска: **GigaAM v3** (Сбер, лучшее качество для русского,
  текст сразу с пунктуацией), whisper на CPU (faster-whisper) или на GPU
  (mlx-whisper, Metal на Apple Silicon).
- **Один поток из двух каналов** — микрофон и системный звук (звонок) склеиваются
  на сервере в единую шкалу времени и распознаются одним проходом; эхо из колонок
  не создаёт дублей, потому что копия голоса совпадает по времени с оригиналом.
- **Диаризация с памятью** — «отпечаток» голоса (ECAPA-TDNN) сверяется с глобальной
  базой спикеров: человек узнаётся и на следующих встречах. Профиль владельца («Вы»)
  обучается автоматически по голосу, доминирующему в микрофоне, — поэтому за одним
  микрофоном могут сидеть несколько человек, их разделит по тембру. Ошибки чинятся
  вручную: на вкладке «Спикеры» можно прослушать образцы голоса и объединить два
  профиля — реплики переписываются во всех встречах.
- **Протокол от локальной LLM** — по окончании встречи Ollama (qwen3:4b) составляет
  итог: краткое описание → ключевые темы → решения → задачи. Экспорт в `.md` / `.txt`.
- **Подсказки ИИ во время встречи** *(экспериментально)* — модель периодически
  комментирует ход обсуждения.
- **Клиент-серверная архитектура** — клиент лёгкий (Electron), все модели на сервере.
  Сервер запускается локально **или** на сервере организации — тогда сотрудникам
  не нужно «тянуть» модели на свои машины.

## Архитектура

```
Клиент (Electron + React + TS)          Сервер (Python + FastAPI)
┌─────────────────────────┐             ┌────────────────────────────────────┐
│ микрофон  ─┐            │  WebSocket  │ микшер каналов → денойз* → VAD →   │
│ система   ─┴→ PCM16 16k │ ──────────► │ → ASR (GigaAM / whisper) →         │
│ (loopback / BlackHole)  │ ◄────────── │ → ECAPA-эмбеддинг → база голосов → │
│ чат, спикеры, история   │   события   │ → SQLite → события клиенту         │
└─────────────────────────┘             │ Ollama: протокол и подсказки       │
                                        └────────────────────────────────────┘
```

Этапы конвейера обособлены (`audio/mixer.py`, `audio/denoise.py`, `audio/vad.py`,
`asr/`, `diarization/`) и заменяются независимо. Микшер помнит энергию каждого
канала: по ней диаризация понимает, из комнаты голос (микрофон) или из звонка.
*денойз — заготовка (по умолчанию `off`): современные ASR обучены на шумной
речи, включать чистку стоит только по результатам замеров.

## Установка клиента (готовые сборки)

Инсталляторы собираются командами `npm run dist:mac` (`.dmg`) и
`npm run dist:win` (`.exe`, NSIS) в папке `client`, а также автоматически в
GitHub Actions (workflow «Build installers», артефакты у каждого запуска).

Сборки не подписаны сертификатом разработчика, поэтому при первом запуске:
- **macOS**: правый клик по приложению → «Открыть» (или снять карантин:
  `xattr -cr /Applications/Стенограф.app`). Приложение заново попросит доступ
  к микрофону и «Записи экрана и звука системы» — это нормально, у
  упакованного приложения свои разрешения.
- **Windows**: в предупреждении SmartScreen — «Подробнее» → «Выполнить в любом
  случае».

Клиенту нужен работающий сервер (локально или адрес сервера организации в
Настройках).

## Быстрый старт (локально, macOS/Linux)

Требования: Python 3.11+ (или [uv](https://docs.astral.sh/uv/)), Node.js 20+,
[Ollama](https://ollama.com).

```bash
# LLM-модели (один раз)
ollama pull qwen3:4b    # протоколы встреч
ollama pull qwen3:1.7b  # подсказки в реальном времени (быстрая)

# Всё остальное — одной командой (Ollama + сервер + приложение):
./start.sh
```

При первом запуске сервер сам создаст окружение и скачает модели распознавания.
По частям, если нужно:

```bash
./server/run.sh         # только сервер (окружение создаётся автоматически)
cd client && npm install && npm run dev   # клиент в dev-режиме (Vite + Electron)
```

При первом запуске сервер скачает модели: GigaAM (~530 МБ), ECAPA (~80 МБ),
а при переключении движка — whisper (до ~900 МБ). Всё складывается в
`server/data/models`; первая встреча может стартовать с задержкой.

## Системный звук

Режим «Автоматически» (по умолчанию) захватывает звук системы **без драйверов**
через [electron-audio-loopback](https://github.com/alectrocute/electron-audio-loopback)
(ScreenCaptureKit на macOS, WASAPI loopback на Windows):

| ОС | Как работает |
|---|---|
| **Windows** | Из коробки. |
| **macOS 13+** | При первом запуске разрешите приложению «Запись экрана и звука системы» (Системные настройки → Конфиденциальность) и перезапустите его. macOS Sequoia периодически просит подтвердить разрешение повторно — это системное поведение. |
| **macOS ≤ 12 / браузер** | Запасной путь: виртуальный аудиокабель [BlackHole](https://github.com/ExistentialAudio/BlackHole) (`brew install blackhole-2ch`), затем в «Настройка Audio-MIDI» — «Устройство с несколькими выходами» (динамики + BlackHole) как системный выход, а BlackHole выбрать источником в приложении. |

Важно: Electron должен оставаться на ветке 35.x — в Electron 40+ регрессия,
loopback-аудио на macOS возвращает тишину
([electron#49607](https://github.com/electron/electron/issues/49607)).

Совет: в наушниках качество диаризации выше — голоса собеседников не попадают
в микрофон через комнату и не смешиваются с вашим голосом (дублей реплик микшер
не допускает в любом случае, но «комнатная» копия голоса портит тембр).

## Сервер организации

Сервер поднимается на общей машине так же, как локально (`server/run.sh`,
`HOST=0.0.0.0`), рядом нужна Ollama. В клиенте: **Настройки → Адрес сервера** →
`http://<хост>:8765` — звук стримится по WebSocket, модели живут на сервере.

## Конфигурация сервера

Все параметры — переменные окружения с префиксом `STENOGRAF_` (или `server/.env`):

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `STENOGRAF_ASR_ENGINE` | `faster_whisper` | Движок: `gigaam` / `faster_whisper` (CPU) / `mlx` (GPU, Apple Silicon) |
| `STENOGRAF_ASR_MODEL` | `small` | whisper: `tiny`/`base`/`small`; gigaam: `v3_e2e_rnnt`/`v3_e2e_ctc` |
| `STENOGRAF_ASR_LANGUAGE` | `ru` | Язык распознавания whisper (`auto` — автоопределение); GigaAM всегда русский |
| `STENOGRAF_SPEAKER_MATCH_THRESHOLD` | `0.35` | Порог «тот же голос» (косинусная близость, см. `scripts/eval_voices.py`) |
| `STENOGRAF_SPEAKER_CHANNEL_DOMINANCE` | `2.0` | Во сколько раз канал должен быть громче, чтобы считаться источником голоса |
| `STENOGRAF_DENOISE` | `off` | Этап чистки шума в конвейере (заготовка) |
| `STENOGRAF_SUMMARY_MODEL` | `qwen3:4b` | Модель Ollama для протокола |
| `STENOGRAF_HINTS_MODEL` | `qwen3:1.7b` | Модель Ollama для подсказок |
| `STENOGRAF_OLLAMA_URL` | `http://127.0.0.1:11434` | Адрес Ollama |
| `STENOGRAF_HINTS_INTERVAL_S` | `25` | Период подсказок ИИ |
| `STENOGRAF_DATA_DIR` | `server/data` | БД, модели, образцы голосов, записи |

Движок и модель, выбранные в настройках приложения, сохраняются в
`data/asr.json` и имеют приоритет над переменными окружения.

## Выбор модели распознавания

Замер на синтезированной русской речи с терминами и именами
(`scripts/bench_asr.py`, MacBook Air M3, 8 ГБ; WER — доля ошибочных слов,
×RT — во сколько раз быстрее реального времени):

| Модель | WER | Скорость | RAM |
|---|---|---|---|
| **GigaAM v3 rnnt** (CPU) — по умолчанию | **1.2%** | 14×RT | ~1.1 ГБ |
| GigaAM v3 ctc (CPU) | 4.9% | 13×RT | ~1.2 ГБ |
| faster-whisper small (CPU) | 9.8% | 2–3×RT | ~530 МБ |
| mlx small q4 (GPU) | 13.4% | 10–14×RT | ~340 МБ |
| mlx base q4 (GPU) | 19.5% | 27×RT | ~240 МБ |
| faster-whisper base (CPU) | 20.7% | 6–10×RT | ~290 МБ |
| faster-whisper tiny (CPU) | 28.0% | 15–20×RT | ~280 МБ |
| mlx tiny q4 (GPU) | 35.4% | 42×RT | ~100 МБ |

Синтетическая речь чище живой, поэтому абсолютные числа занижены, но
соотношение моделей сохраняется. Практический вывод: **GigaAM v3 rnnt** —
одновременно самая точная (одна ошибка на 82 слова, сразу с пунктуацией)
и одна из самых быстрых, поэтому она и стоит по умолчанию. Whisper остаётся
запасным вариантом: `small` — если не хватает памяти (GigaAM тяжелее на
~600 МБ), `mlx` — если важно разгрузить CPU, мультиязычность — только whisper
(GigaAM распознаёт русский).

## Тесты

```bash
cd server
.venv/bin/pip install -r requirements-dev.txt   # один раз (pytest)

.venv/bin/python -m pytest                  # юнит-тесты: логика диаризации,
                                            # порог, дрейф отпечатков, merge, микшер
.venv/bin/python -m pytest -m integration   # + реальная ECAPA на синтезированных
                                            # голосах macOS (медленно)
.venv/bin/python -m pytest -m e2e           # встречи целиком: одноразовый сервер +
                                            # WebSocket-клиент (эхо, память голосов,
                                            # обрыв связи, REST, переключение ASR)
```

Ручной чек-лист перед показом (реальный микрофон, звонки, железо) — [TESTING.md](TESTING.md).

Инструменты для проверки на реальных данных (папка `server/scripts`):

- **`eval_voices.py`** — проверка диаризации на живых голосах: каждый участник
  наговаривает несколько фраз (`--dir voices/`, папка = человек) или берутся
  образцы из вкладки «Спикеры» (`--samples`). Показывает близости голосов и
  таблицу «порог → сколько профилей получится» — так подбирается
  `SPEAKER_MATCH_THRESHOLD`.
- **`bench_asr.py`** — сравнение всех ASR-моделей по качеству (WER) и скорости
  на синтезированной речи (таблица выше).

## Ограничения (честно)

- Диаризация по коротким репликам (<1 с) неточна — такие реплики приписываются
  последнему говорившему; порог настраивается.
- Каналы распознаются единым смешанным потоком: если два человека говорят
  строго одновременно, в транскрипт попадёт в основном тот, кто громче
  (раздельные каналы справлялись бы лучше ценой двойной нагрузки и дублей эха).
- Подсказки ИИ — демо-режим: на машине с 8 ГБ RAM одновременная работа ASR и LLM
  на пределе, поэтому подсказки редкие (раз в ~25 с).
- Протокол длинной встречи (>~40 мин разговора) строится по сокращённому
  транскрипту (начало + конец) из-за контекста локальной модели.
